## Softmax의 axis

다중 분류 logits가 `[B, C]`라면 `axis=-1`을 사용한다.

- `B`: 샘플 수
- `C`: 클래스 수
- 각 샘플마다 `C`개의 logit을 Softmax에 넣어 클래스별 확률로 변환
- 각 샘플의 클래스 확률 합은 1

즉 `axis=-1`은 마지막 축인 클래스 `C`축을 계산한다는 의미이다.

## 큰 Logits와 Max Trick

`[1000, 1001, 1002]`처럼 큰 logits를 그대로 `exp()`에 넣으면 overflow로 `inf`가 발생할 수 있다.

이후 Softmax에서 `inf / inf`가 계산되면 `nan`이 발생할 수 있다.

이를 막기 위해 모든 logits에서 가장 큰 값을 뺀다.

$$z_i'=z_i-\max(z)$$

그러면 가장 큰 logit은 `0`, 나머지는 음수가 되어 지수 계산이 안정적이 된다.

같은 값을 모든 logits에서 빼도 Softmax 확률은 변하지 않는다.

## Log-Softmax를 사용하는 이유

Cross Entropy에서는 결국 정답 클래스의 `log(probability)`가 필요하다.

`softmax → log`를 따로 계산하는 것보다 `log-softmax`를 직접 계산하는 것이 수치적으로 더 안정적이다.

## `logits`, `targets`는 어디서 오는가?

함수 안의

`logits = np.asarray(logits, dtype=np.float64)`

는 새로운 데이터를 선언하는 것이 아니다.

함수의 매개변수로 전달받은 `logits`, `targets`를 NumPy 배열로 바꾸고 자료형을 맞추는 과정이다.

따라서 다음과 같이 함수를 호출하려면 `logits`, `targets`의 실제 데이터가 함수 밖에서 먼저 만들어져 있어야 한다.

`cross_entropy_from_logits(logits, targets)`

앞 셀에서 만든 변수를 뒤 셀에서 그대로 사용할 수도 있다.

## One-hot Label과 Class Index

클래스가 3개이고 정답이 2번 클래스라면:

- One-hot label: `[0, 0, 1]`
- Class index: `2`

표현 방법은 다르지만 둘 다 **정답이 2번 클래스라는 동일한 정보**를 나타낸다.

Class index의 `0`, `1`, `2`는 여러 정답을 의미하는 것이 아니라 샘플 하나의 정답 클래스 번호이다.

## `target_index`

`target_index=2`로 함수를 호출했다면 정답 클래스 번호 `2`를 함수에 직접 전달한 것이다.

Cross Entropy에서는 해당 정답 클래스의 확률을 선택해 loss를 계산한다.

## 문제 유형별 손실 함수

- 회귀: `MSE`, PyTorch에서는 `MSELoss`
- 이진 분류: `BCE`, PyTorch에서는 `BCEWithLogitsLoss`
- 다중 분류: `Cross Entropy`, PyTorch에서는 `CrossEntropyLoss`

## BCE에서 `log(0)`을 피하는 이유

BCE에서는 `log(p)` 또는 `log(1-p)`를 계산한다.

확률이 정확히 `0` 또는 `1`이면 계산 과정에서 `log(0)`이 발생하고 `-inf`가 생길 수 있다.

이를 막기 위해 확률을 다음 범위로 clipping한다.

$$[\epsilon,1-\epsilon]$$

`epsilon`은 0을 피하기 위한 아주 작은 값이다.

## Cross Entropy와 정답 확률

정답 클래스의 확률을 `p`라고 하면 Cross Entropy loss는 다음과 관련된다.

$$L=-\log(p)$$

정답 클래스의 확률이 `1`에 가까워질수록 loss는 `0`에 가까워지므로 **감소한다**.

## Gradient는 `w`만 바꾸는가?

아니다.

`y = wx + b`에서 학습 가능한 파라미터가 `w`, `b`라면 Gradient Descent는 둘 다 갱신한다.

예측:

$$\hat{y}_i=wx_i+b$$

오차:

$$e_i=\hat{y}_i-y_i$$

MSE:

$$L=\frac{1}{n}\sum_{i=1}^{n}(\hat{y}_i-y_i)^2$$

`w`에 대한 gradient:

$$\frac{\partial L}{\partial w}=\frac{2}{n}\sum_{i=1}^{n}(\hat{y}_i-y_i)x_i$$

`b`에 대한 gradient:

$$\frac{\partial L}{\partial b}=\frac{2}{n}\sum_{i=1}^{n}(\hat{y}_i-y_i)$$

즉 파라미터마다 각각의 gradient가 존재한다.

## Gradient의 의미

`gradient`의 일반적인 한국어 의미는 **기울기, 변화율**이다.

딥러닝에서는 loss가 각 파라미터에 대해 얼마나, 어느 방향으로 변하는지를 나타낸다.

## `np.seterr()`와 `np.errstate()`

`np.seterr()`는 NumPy의 오류 처리 방식을 설정한다.

예:

`np.seterr(over="raise", invalid="raise")`

overflow나 invalid 연산이 발생했을 때 예외를 발생시키도록 설정한다.

반면 `np.errstate()`는 특정 `with` 구간에서만 오류 처리 방식을 임시로 바꾼다.

- `np.seterr()` → error 처리 방식 설정
- `np.errstate()` → 특정 구간의 error state를 임시 설정

## 학습 결과가 중복 출력된 것처럼 보인 이유

`train_linear_regression()` 함수 내부에서 `step=0`, `step=40` 같은 중간 학습 결과를 출력하고 있었다.

를 각각 출력한 것이다.

`lr=0.5`에서 매우 큰 숫자가 나왔는데도 `FloatingPointError`가 발생하지 않은 것은 값이 매우 크더라도 아직 `inf`가 아닌 유한한 숫자였기 때문이다.
