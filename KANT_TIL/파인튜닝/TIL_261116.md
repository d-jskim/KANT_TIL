
# 1. 파인튜닝

## 1.1 파인튜닝 정의
`파인튜닝(Fine-tuning)`: 사전학습된 모델을 특정 도메인이나 업무에 맞게 추가 학습하여 모델의 **가중치**를 조정하고 성능을 개선하는 기법

## 1.2 Prompt, RAG, Fine-tuning, Pre-training 사용 목적

| 방식           | 목적               | 예시               |
| ------------ | ---------------- | ---------------- |
| Prompt       | 지금 어떻게 답할지 지시    | "3줄로 설명해줘"       |
| RAG          | 외부 지식을 찾아서 답변    | "사내 규정 검색"       |
| Fine-tuning  | 모델의 행동 패턴 자체를 조정 | 항상 회사 상담 형식으로 답변 |
| Pre-training | 모델의 기본 능력 자체를 학습 | GPT 같은 기반 모델 제작  |
- `Prompt → RAG → Fine-tuning` 순으로 검토
- 프롬프트와 RAG로 해결되지 않는 반복적인 행동 패턴이 있을 때 필요함

## 1.3 RAG와 Fine-tuning의 차이
### 1.3.1 RAG와 Fine-tuning 상세 설명

| 구분       | RAG              | Fine-tuning    |
| -------- | ---------------- | -------------- |
| 정보 제공 시점 | 질문할 때(추론 시점)     | 추가 학습할 때       |
| 정보 제공 방법 | 검색한 문서를 프롬프트에 포함 | 학습 데이터로 반복 학습  |
| 모델 가중치   | 변경 없음            | 변경됨            |
| 정보 활용    | 제공된 문서를 참고하여 답변  | 학습된 패턴과 지식을 활용 |
| 정보 변경    | 문서 업데이트 후 재검색    | 필요에 따라 재학습     |
| 주요 목적    | 외부 지식 활용         | 모델의 행동과 성능 조정  |
![[Pasted image 20261116145403.png]]

### 1.3.2 RAG와 Fine-tuning의 해결 문제
| 문제                          | 우선 검토 방법                   |
| --------------------------- | -------------------------- |
| 최신 규정을 모름                   | RAG                        |
| 답변 형식을 지키지 않음               | Prompt / Structured Output |
| 복잡한 **상담 패턴**을 반복적으로 잘못 처리함 | Fine-tuning                |
| 최신 규정과 특화된 답볍 방식이 모두 필요함    | RAG + Fine-tuning          |
- RAG 검색 결과가 정확한데 답변이 잘못된 경우, 무조건 검색 성능을 개선하는 것이 아니라 답변 생성 단계에서 무엇인지 확인해야 함

## Fine-tuning의 필요성
- RAG로 규정을 정확하게 검색했는데도 모델이 답변을 자유롭게 작성할 때 적용
	- 1차) Prompt Engineering: 시스템 프롬프트에 답변 형식 명시
	- 2차) Structured Output: 출력 형식 구조 제약
	- 3차) Fine-tuning: 프롬프트와 structured output으로 해결되지 않는 복잡한 답변 패턴이 있다면, 올바른 질문·답변 예시를 학습시킴
	  -> 수백~수천 개의 상담 사례와 모범 답변을 사용해 회사가 원하는 판단 방식이나 답변 스타일을 익힘
