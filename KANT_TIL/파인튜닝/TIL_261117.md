

# 2026.11.17 파인튜닝 학습 정리

## 1. 토큰 및 모델 처리

### 토큰 수 상한 (`MAX_LENGTH`)
- 입력 프롬프트와 모범 답변의 토큰 길이를 고려하여 설정
- 데이터셋의 입력·출력 길이 분포와 모델의 최대 컨텍스트 길이를 확인한 후 결정
- 토큰 수는 GPU 메모리 사용량, 연산 비용, 지연 시간(Latency)에 영향을 미침
- 학습 시 너무 짧게 설정하면 입력이나 정답이 잘릴 수 있으므로 주의

### 입력과 출력 분리
- Causal LLM은 입력 프롬프트에 이어 다음 토큰을 생성하는 구조
- 생성 결과에 입력 토큰과 출력 토큰이 함께 포함될 수 있음
- `prompt_ids`와 `full_ids`의 길이를 이용해 입력 부분을 제외하고 생성된 답변만 추출
- 단, 모델 API에 따라 생성된 토큰만 반환하는 경우도 있음

### 토크나이저(Tokenizer)
- LLM은 토큰 단위로 학습하고 다음 토큰의 확률 분포를 예측
- 토크나이저를 변경하면 토큰 분할 및 ID가 달라져 모델 응답에 영향을 미침
- 학습된 모델과 호환되는 토크나이저를 함께 사용해야 함
- 특수 토큰(Special Token)의 종류와 ID는 모델마다 다를 수 있음

## 2. Context Engineering

- 중요한 지시사항과 문서는 모델이 효과적으로 참고할 수 있도록 배치
- 중요한 문서를 앞부분에 배치하는 것은 하나의 전략이지만, 항상 최선은 아님
- 문서의 관련성, 우선순위, 컨텍스트 길이, 모델 특성을 고려하여 배치 순서 결정

## 3. 파인튜닝 데이터셋

### 데이터셋 규모 및 목적
- 약 1,000개 수준의 고품질 데이터로 답변 형식이나 행동 정렬(Alignment)을 개선하는 실험 가능
- 필요한 데이터 규모는 모델, 학습 목적, 데이터 품질 및 다양성에 따라 달라짐
- 1,000개가 충분하다는 일반적 기준은 아니므로 관련 논문 및 실험 결과 확인 필요
- 데이터셋에서 어떤 특징과 패턴을 학습시킬 것인지 사전 정의

### 데이터셋 확보
- Hugging Face: 공개 데이터셋 검색 및 활용
- AI-Hub: 국내 AI 학습용 데이터셋 확보
- 반합성 데이터(Semi-synthetic Data): 실제 데이터와 인공적으로 생성한 데이터를 결합하여 구성

### 데이터 라이선스
- 데이터셋별 이용약관과 라이선스 확인 필요
- 기업에서 활용할 경우 상업적 이용, 재배포, 수정 및 모델 학습 허용 범위 검토
- 개인정보, 저작권, 데이터 출처 및 사용 조건 확인

## 4. 코드 및 데이터 검증

### `assert`와 `raise`
- `assert`: 개발 과정에서 내부적으로 성립해야 하는 조건 검증
- `raise`: 외부 입력이나 실행 환경 등에서 발생하는 오류를 명시적으로 처리
- `assert`는 최적화 실행 시 비활성화될 수 있으므로 필수 입력 검증에는 사용하지 않는 것이 적절

### 사전 검증의 필요성
- GPU 학습 이전에 데이터 형식, 토큰 길이, 필수 필드 및 값 검증
- 잘못된 데이터로 인한 학습 실패 및 불필요한 GPU 사용 비용 방지

### JSON 저장
- `ensure_ascii=False`: 비ASCII 문자를 Unicode 이스케이프 문자로 변환하지 않고 저장
- 한글을 읽을 수 있는 형태로 유지하며, 실제 인코딩 문제는 UTF-8 설정도 확인 필요

## 5. 실무 적용 시 고려사항

- 학습 목적에 적합한 데이터셋의 특징과 품질 검토
- 모델과 토크나이저의 호환성 확인
- 입력·출력 토큰 길이에 따른 학습 자원 및 비용 관리
- 학습 전 데이터와 실행 환경 검증
- 학습 데이터의 출처, 저작권 및 상업적 이용 가능 여부 확인
- 파인튜닝 효과에 관한 논문과 실험 결과를 근거로 데이터 규모 및 학습 전략 결정
