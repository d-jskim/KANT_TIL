#### Q. dead ReLU
```
Linear 출력 z < 0
     ↓
ReLU 출력 = 0
     ↓
기울기 = 0
     ↓
해당 뉴런의 가중치가 더 이상 학습되지 않음
```
- 16개 중 1개가 죽으면 → 나머지 15개 뉴런은 계속 학습하므로 모델은 작동함
- 16개가 전부 죽으면 → 다음 층에 모두 0이 전달되어 입력 정보가 차단되는 심각한 상황
- 첫 번째 은닉층 일부가 죽어도 두 번째 은닉층의 뉴런들이 자동으로 죽는 것은 아님

-  해결책
	- 가장 직접적인 해결책은 LeakyReLU
		- 음수에서도 작은 값을 남김
	- 학습률 낮추기
	- Kaiming 초기화 사용
	- GELU·SiLU 같은 부드러운 활성화 함수로 교체

#### Q. ReLU가 0으로 만드는 것의 의도
※ deadReLU는 모든 입력에서 계속 0이 되는 것이 문제
(즉, 한 뉴런이 영구적으로 0만 출력하는 것이 위험함)
```
Dead ReLU 뉴런
데이터 A: -2 → 0
데이터 B: -3 → 0
데이터 C: -1 → 0
모든 데이터에서 계속 0 → 학습 중단
```
- 정상 뉴런
```
정상 ReLU 뉴런
데이터 A: -2 → 0
데이터 B:  3 → 3
데이터 C: -1 → 0
```

- **ReLU가 음수를 0으로 만드는 이유**
	- 모델에 **비선형성**을 추가해 복잡한 패턴을 학습함
	- 불필요한 특징을 0으로 만들어 필요한 뉴런만 활성화함
	- 양수 영역의 기울기가 `1`이라 Sigmoid보다 기울기 소실이 적음
	- 계산이 `max(0, x)`로 매우 단순하고 빠름


#### Q. ReLU, LeakyReLU, GELU 비교
- **ReLU**: 0을 기준으로 음수는 완전히 제거하고 양수는 통과
$$
f(x)=max(0,x)
$$
- **LeakyReLU**: 음수를 완전히 제거하지 않고 작게 남김. 하지만 0에서 기울기가 바뀌므로 여전히 꺾인 형태
$$
f(x)=
\begin{cases}
x, & x>0 \\
0.01x, & x\leq0
\end{cases}
$$
- **GELU**: 0을 기준으로 딱 끊지 않고, 0 주변의 값을 부드럽게 줄이거나 통과시킴
$$
GELU(x)=xΦ(x)
$$
```
ReLU      : 음수 ──[0에서 딱 끊음]── 양수
LeakyReLU : 음수 조금 남김 ──[0에서 꺾임]── 양수
GELU      : 음수에서 양수까지 부드럽게 연결
```


- 은닉층 : ReLU 함수
- 출력층 : Sigmoid - 이진 분류 / Softmax - 다중 분류

#### detach()

- 텐서를 PyTorch의 **자동미분 계산 그래프에서 분리**하는 함수
- 텐서의 값은 유지되지만 `requires_grad=False`가 되어 역전파에 사용되지 않음
- 원본 텐서의 계산 그래프는 그대로 유지됨
- 시각화, 결과 확인, NumPy 변환처럼 **값만 사용할 때** 주로 사용

```python
result = output.detach()
```

```python
output.requires_grad
# True

result.requires_grad
# False
```

#### NumPy 배열로 변환

```python
result = output.detach().cpu().numpy()
```

#### 사용 시 주의

손실함수에 전달하기 전에 `detach()`하면 학습 경로가 끊어진다.

```python
# 잘못된 사용
loss = criterion(output.detach(), target)
```

> `detach()`는 텐서의 값을 없애는 것이 아니라, 해당 텐서를 통한 기울기 계산과 역전파를 차단한다.



#### XOR 구분 ReLU hidden

|항목|의미|판단|
|---|---|---|
|`XOR acc`|기본 XOR 데이터 4개에 대한 분류 정확도|높을수록 좋음|
|`noisy valid acc`|노이즈가 포함된 검증 데이터에 대한 정확도|높을수록 일반화·강건성이 좋음|
|`params`|모델이 학습하는 전체 가중치와 편향의 개수|적을수록 모델이 가벼움|
|`latency`|입력을 받아 예측 결과를 출력하는 데 걸리는 추론 시간|짧을수록 빠름|

```
XOR acc         → 기본 문제를 학습했는가?
noisy valid acc → 변형된 데이터에도 잘 작동하는가?
params          → 모델이 얼마나 큰가?
latency         → 예측이 얼마나 빠른가?
```
