## 1. Generator, Seed, 난수 생성의 관계

`Generator`는 난수 생성의 내부 상태를 관리하는 객체이고, `torch.randn()` 같은 연산이 그 상태를 사용해 실제 값을 만든다.

| 구분 | 항목 | 역할 |
|---|---|---|
| 난수 관리 | `torch.Generator()` | 별도의 난수 생성기 객체 생성 |
| 난수 관리 | `generator.manual_seed(42)` | 해당 생성기를 Seed 42의 초기 상태로 설정 |
| 난수 사용 | `torch.randn(3)` | 표준정규분포에서 값 3개를 생성 |
| 난수 사용 | `random_split()` | 난수 생성기를 이용해 원본 인덱스를 무작위 분할 |
| 난수 사용 | `DataLoader(shuffle=True)` | 이미 정해진 Dataset의 조회 순서를 섞음 |

### 1.1 Seed를 변수에 할당하지 않아도 영향을 주는 이유

`torch.randn()`에 `generator`를 지정하지 않으면 PyTorch의 기본 난수 생성기를 사용한다. `torch.manual_seed()`는 그 기본 생성기의 상태를 설정한다.

```python
import torch
torch.manual_seed(42)
x1 = torch.randn(3)
torch.manual_seed(42)
x2 = torch.randn(3)
print(torch.allclose(x1, x2))  # True
```

`x1`·`x2`에 Seed를 넣은 것이 아니다. 두 번의 난수 생성 전에 같은 기본 생성기를 같은 초기 상태로 되돌린 것이다.

`set_seed()`는 PyTorch 기본 함수명이 아니다. 교안에서 정의한 함수라면 그 내부에서 `torch.manual_seed()` 등을 호출하는지 확인한다.

생성기를 명시하면 연결 관계가 드러난다.

```python
g = torch.Generator().manual_seed(42)
x1 = torch.randn(3, generator=g)
g.manual_seed(42)
x2 = torch.randn(3, generator=g)
print(torch.allclose(x1, x2))  # True
```

### 1.2 두 Generator에 같은 Seed를 주면

```python
split_generator = torch.Generator().manual_seed(42)
loader_generator = torch.Generator().manual_seed(42)
```

- 별개의 객체이지만 초기 난수 상태는 같다.
- 같은 환경에서 같은 난수 연산을 같은 조건·순서로 호출하면 같은 결과가 나온다.
- 한 생성기를 사용해도 다른 생성기의 상태는 진행되지 않는다.
- `random_split()`은 전체 데이터의 소속을 나누고, Loader는 이미 나뉜 학습 데이터의 조회 순서를 섞는다. 대상과 난수 호출 과정이 다르므로 Seed가 같다고 최종 결과가 같아지는 것은 아니다.
- 시작부터 서로 다른 난수 흐름을 사용하려면 Seed를 각각 `42`, `43`처럼 다르게 설정할 수 있다.

`42` 자체에 성능상 이점은 없다. Seed가 바뀌면 초기 가중치나 데이터 분할 등이 달라져 실제 실험 결과는 달라질 수 있다.

Seed를 한 번 고정했다고 모든 난수 호출이 같은 값을 반환하는 것은 아니다. 사용하면서 생성기 상태가 진행되므로, 학습 Epoch마다 Shuffle 순서도 달라질 수 있다.

## 2. 행렬곱과 가중치의 행·열 방향

```python
num_samples = 240
X = torch.randn(num_samples, 4)  # (240, 4)
true_W = torch.tensor([
    [1.0, -1.0, 0.5],
    [0.5, 1.5, -1.0],
    [-1.0, 0.5, 1.0],
    [1.0, 0.2, -0.5],
])  # (4, 3)
scores = X @ true_W             # (240, 3)
y = scores.argmax(dim=1)        # (240,)
```

행렬곱은 앞 행렬의 열 개수와 뒤 행렬의 행 개수가 같으면 가능하다.

$$(240,4)\times(4,3)=(240,3)$$

- `X`의 행 240개: 샘플 240개.
- `X`의 열 4개: 입력 특성 `x1`, `x2`, `x3`, `x4`.
- `true_W`의 행 4개: 입력 특성별 가중치.
- `true_W`의 열 3개: 클래스 0·1·2에 대한 가중치.

| 입력 특성 | 클래스 0 | 클래스 1 | 클래스 2 |
|---|---|---|---|
| `x1` | 1.0 | -1.0 | 0.5 |
| `x2` | 0.5 | 1.5 | -1.0 |
| `x3` | -1.0 | 0.5 | 1.0 |
| `x4` | 1.0 | 0.2 | -0.5 |

첫 번째 행 `[1.0, -1.0, 0.5]`는 `x1`이 클래스 0·1·2에 미치는 가중치다.

클래스 0 점수는 `X`의 한 행과 `true_W`의 첫 번째 열을 곱해서 더한다.

$$s_0=1.0x_1+0.5x_2-1.0x_3+1.0x_4$$

다른 두 열도 같은 방식으로 계산하므로 샘플마다 점수 3개가 나온다. `argmax(dim=1)`은 각 행에서 가장 큰 점수의 열 번호를 선택한다. `y`는 값이 0·1·2 중 하나인 정답 클래스 번호 240개다.

여기서는 미리 정한 `true_W`로 연습용 정답을 만드는 것이며, 학습으로 얻은 가중치가 아니다.

### nn.Linear와 방향이 다른 이유

`nn.Linear(4, 3)`의 `weight`는 `(출력, 입력) = (3, 4)`로 저장되고, 계산할 때 `X @ weight.T + bias`를 수행한다.

직접 작성한 `true_W`는 `X @ true_W`에 바로 사용할 수 있도록 `(입력, 출력) = (4, 3)`으로 만든 것이다.

## 3. 추론과 state_dict

### 3.1 추론(Inference)

추론은 모델의 가중치를 업데이트하지 않고 입력에 대한 예측값을 계산하는 과정이다. 순전파는 실행하지만 일반적인 추론에서는 정답 라벨·손실 계산·역전파·Optimizer 업데이트가 필요하지 않다.

```python
model.eval()  # Dropout·BatchNorm 등을 평가 동작으로 전환
with torch.no_grad():  # 역전파용 연산 기록을 만들지 않음
    prediction = model(new_x)
```

`model.eval()`과 `torch.no_grad()`는 역할이 다르다. `eval()`만 호출한다고 기울기 기록이 꺼지는 것은 아니다.

### 3.2 state_dict의 의미

`state_dict()`는 객체의 현재 상태를 딕셔너리로 반환하는 PyTorch 메서드다. 사용자가 내부 구조를 직접 만들 필요는 없다.

```python
model_state = model.state_dict()
optimizer_state = optimizer.state_dict()
```

| 구분 | 항목 | `model.state_dict()` | `optimizer.state_dict()` |
|---|---|---|---|
| 저장 내용 | 주요 값 | 가중치·편향·저장 대상 버퍼 | 알고리즘별 누적 상태·파라미터 그룹 설정 |
| 저장 내용 | 예시 | `weight`, `bias`, BatchNorm 통계 | 학습률, 모멘텀, Adam 누적값·Step |
| 사용 목적 | 추론 | 저장된 모델 상태 복원에 사용 | 일반적으로 불필요 |
| 사용 목적 | 학습 재개 | 현재 모델 값 복원 | 기존 업데이트 상태를 이어갈 때 복원 |

- `model.state_dict`: 메서드 자체.
- `model.state_dict()`: 메서드를 호출해 얻은 딕셔너리.
- 키는 등록한 계층 이름을 바탕으로 생성된다. 예: `fc1.weight`, `fc1.bias`.
- 모델 구조 자체는 일반적으로 포함하지 않으므로, 같은 구조의 모델을 먼저 만들고 상태를 불러온다.
- 학습 전에도 호출할 수 있다. 이때는 초기화된 가중치·편향 등이 담긴다.

## 4. 모델 상태 저장·복원과 예측 비교

```python
from pathlib import Path
import torch
from torch import nn
path = Path("temp_state.pt")
model = nn.Linear(2, 1)  # 가중치 2개·편향 1개 초기화
x = torch.randn(3, 2)    # 특성 2개인 샘플 3개
with torch.no_grad():
    pred_before = model(x)  # (3, 1)
torch.save(model.state_dict(), path)
loaded_model = nn.Linear(2, 1)  # 구조가 같은 별도 객체
loaded_state = torch.load(path, map_location="cpu")
loaded_model.load_state_dict(loaded_state)
with torch.no_grad():
    pred_after = loaded_model(x)
print("same_prediction:", torch.allclose(pred_before, pred_after))
# same_prediction: True
```

- `torch.save()`: 상태 딕셔너리를 파일로 저장.
- `torch.load()`: 파일에서 객체를 읽음. `map_location="cpu"`는 저장된 Tensor를 CPU로 읽도록 지정.
- `load_state_dict()`: 읽은 상태를 기존 모델 객체에 적용. 새 모델의 초기 가중치·편향이 저장된 값으로 바뀜.
- `torch.allclose()`: 모든 원소가 허용 오차 범위 안에서 같은지 비교.

입력과 가중치·편향이 같으므로 예측도 같다. 이 예제에는 학습 과정이 없으며, 저장·복원이 되는지 확인하는 실습이다.

## 5. 체크포인트와 학습 재개

### 5.1 여러 상태를 묶어 저장

각 `state_dict()`의 내부 구조는 PyTorch가 만들지만, 여러 상태를 묶는 바깥쪽 딕셔너리는 사용자가 구성한다.

```python
torch.save({
    "model_state": model.state_dict(),
    "optimizer_state": optimizer.state_dict(),
    "epoch": epoch,
}, path)
```

`"model_state"` 같은 바깥쪽 키 이름은 직접 정한 것이다. 읽을 때 저장한 키와 동일하게 사용해야 한다.

### 5.2 epoch를 반환하는 이유

```python
def load_checkpoint(path, model, optimizer):
    ckpt = torch.load(path, map_location="cpu")
    model.load_state_dict(ckpt["model_state"])
    optimizer.load_state_dict(ckpt["optimizer_state"])
    return ckpt["epoch"]
last_epoch = load_checkpoint(path, model, optimizer)
start_epoch = last_epoch + 1
```

- `model`·`optimizer`는 전달받은 객체의 상태가 직접 변경되므로 반환하지 않아도 복원된다.
- `epoch`는 호출한 쪽에서 다음 학습 시작 번호를 정하도록 반환한다.
- 저장된 값이 마지막 완료 Epoch 번호라면, `5`를 읽었을 때 다음 번호 `6`부터 시작한다.
- 체크포인트에 다음 시작 번호를 저장한 설계라면 `+1`하지 않는다. 저장 규칙과 일치시켜야 한다.

### 5.3 난수 상태까지 저장하는 이유

학습 중에는 가중치 초기화, Shuffle, 랜덤 데이터 증강, Dropout, 샘플링 등에 난수가 사용된다.

Seed는 초기 상태를 정하는 값이고, 난수 상태는 다음 난수를 이어서 계산하기 위한 현재 내부 상태다. 재개하면서 Seed만 다시 설정하면 중단 지점이 아니라 초기 상태로 돌아간다.

| 구분 | 저장 항목 | 재개 시 목적 |
|---|---|---|
| 기본 재개 | Model·Optimizer 상태 | 가중치와 업데이트 누적 상태 복원 |
| 기본 재개 | Epoch·최고 검증값 등 | 학습 진행 위치와 최고 기록 복원 |
| 난수 재현 | Python `random.getstate()` | Python 난수 사용 흐름 복원 |
| 난수 재현 | NumPy `np.random.get_state()` | 사용 중인 NumPy 기본 난수 상태 복원 |
| 난수 재현 | `torch.get_rng_state()` | PyTorch CPU 난수 상태 복원 |
| 난수 재현 | `torch.cuda.get_rng_state_all()` | CUDA 장치별 난수 상태 복원 |
| 난수 재현 | `loader_generator.get_state()` | Loader에 전달한 별도 생성기 상태 복원 |
| 학습 제어 | 사용 중인 EarlyStopping 상태 | 최고 점수·연속 비개선 횟수 등을 이어감 |
| 학습 제어 | 사용 중인 Scheduler 등의 상태 | 학습률 변화 등 제어 흐름을 이어감 |

난수 상태를 항상 저장해야 하는 것은 아니다. 단순히 학습을 이어가는 것은 가능하지만, 중단하지 않았을 때와 같은 학습 흐름을 재현하려면 관련 난수 상태도 복원해야 한다.

EarlyStopping 상태는 난수가 아니라 학습 중단 판단을 위한 상태다.

난수 상태만으로 모든 환경에서 완전히 같은 결과가 보장되지는 않는다. 동일한 환경과 결정적 연산 등의 조건이 필요하며, 배치 중간 재개나 여러 Worker 사용 시 추가 관리가 필요할 수 있다.

## 6. best_valid_loss 갱신 조건

```python
is_best = valid_loss < best_valid_loss
if is_best:
    best_valid_loss = valid_loss
    best_epoch = epoch
```

Loss는 작을수록 좋다. 현재 검증 Loss가 지금까지의 최저 검증 Loss보다 작으면 더 좋은 결과이므로 최고 기록을 갱신한다.

예: 기존 최저값 `0.40`, 현재값 `0.35`이면 `is_best = True`다.

`best`는 “가장 큰 숫자”가 아니라 “해당 지표 기준으로 가장 좋은 값”이라는 의미다.

- Loss: 낮을수록 좋으므로 `current < best`.
- Accuracy: 높을수록 좋으므로 `current > best`.
- 현재 코드는 `<`이므로 값이 같으면 갱신하지 않는다.

## 7. Python Dictionary와 JSON

`dict`는 Python 메모리 안의 객체이고, JSON은 데이터를 저장·전송하는 텍스트 형식이다. 모양이 비슷하다고 같은 것은 아니다.

| 구분 | 항목 | Python Dictionary | JSON |
|---|---|---|---|
| 성격 | 정체 | Python 자료형 | 언어에 독립적인 텍스트 형식 |
| 성격 | 값 | Tensor 등 Python 객체도 포함 가능 | 문자열·숫자·배열·객체·Boolean·null 등 |
| 문법 | Key | 문자열·정수·튜플 등 Hashable 객체 | 문자열만 가능 |
| 문법 | 문자열 | 작은따옴표·큰따옴표 가능 | 큰따옴표 사용 |
| 문법 | 참·거짓 | `True`, `False` | `true`, `false` |
| 문법 | 빈 값 | `None` | `null` |

```python
import json
config = {"batch_size": 32, "shuffle": True}
json_text = json.dumps(config)       # dict -> JSON 문자열
restored_config = json.loads(json_text)  # JSON 객체 -> dict
```

JSON 객체를 파일에서 읽으면 Python 안에서는 `dict`가 된다.

```python
with open("config.json", encoding="utf-8") as file:
    config = json.load(file)
```

따라서 “Config JSON”이라고 불러도, Python 코드에서 다루는 `config`의 실제 자료형은 `dict`일 수 있다.

`return {"python": ..., "numpy": {...}, "torch_cpu": ...}` 형태의 난수 상태 코드는 중첩 Dictionary를 반환하는 Python 코드다. 함수 호출 결과와 Tensor 등을 담으므로 JSON 텍스트 자체가 아니다.

`torch.save()`로 딕셔너리를 저장해도 JSON이 되는 것은 아니다. Tensor가 포함된 딕셔너리는 기본 `json.dumps()`로 바로 변환할 수 없다.

## 8. Path 객체와 파일·폴더 작업

`Path`는 경로 정보와 파일·폴더를 다루는 메서드를 제공하는 객체다.

### 8.1 경로를 합치는 것은 괄호가 아니라 /

```python
from pathlib import Path
exp_dir = Path("runs") / "exp01"
name = "config.json"
p = exp_dir / name
```

`exp_dir / name`은 결합된 경로를 나타내는 새 Path 객체를 반환한다. 기존 `exp_dir`는 바뀌지 않는다. 일반 문자열끼리 `"runs" / "config.json"`처럼 사용할 수는 없다.

```python
if not (exp_dir / name).exists():
    print("파일 또는 폴더가 없습니다.")
```

괄호는 결합한 Path 객체 전체에 `.exists()`를 호출하기 위해 묶는다. 위 조건은 다음과 같다.

```python
p = exp_dir / name
if not p.exists():
    print("파일 또는 폴더가 없습니다.")
```

### 8.2 속성과 메서드

`p = Path("runs/config.json")`인 경우:

| 구분 | 코드 | 의미 |
|---|---|---|
| 속성 | `p.name` | 파일명 `"config.json"` |
| 속성 | `p.stem` | 확장자를 제외한 이름 `"config"` |
| 속성 | `p.suffix` | 확장자 `".json"` |
| 속성 | `p.parent` | 상위 경로를 나타내는 `Path("runs")` |
| 메서드 | `p.exists()` | 해당 경로의 존재 여부 |
| 메서드 | `p.is_file()` | 실제 파일인지 확인 |
| 메서드 | `p.is_dir()` | 실제 폴더인지 확인 |
| 메서드 | `p.read_text(encoding="utf-8")` | 파일 내용을 문자열로 읽음 |
| 메서드 | `p.write_text("내용", encoding="utf-8")` | 파일을 생성하거나 기존 내용을 덮어씀 |

속성은 괄호 없이 값을 확인하고, 메서드는 괄호를 붙여 호출한다.

`Path(...)`를 만드는 것만으로 실제 파일이나 폴더가 생기지는 않는다.

### 8.3 폴더 생성

```python
save_dir = Path("checkpoints/run1")
save_dir.mkdir(parents=True, exist_ok=True)
```

- `mkdir()`: 실제 폴더 생성.
- `parents=True`: 없는 상위 폴더도 함께 생성.
- `exist_ok=True`: 해당 폴더가 이미 있어도 오류 없이 사용.
- 같은 경로에 폴더가 아닌 파일이 있는 경우 등까지 모든 오류를 무시하는 옵션은 아니다.

## 9. config·metrics를 JSON 파일로 저장

`config`와 `metrics`가 JSON으로 변환 가능한 값을 담은 딕셔너리라고 가정한다.

```python
exp_dir.mkdir(parents=True, exist_ok=True)
(exp_dir / "config.json").write_text(
    json.dumps(config, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
(exp_dir / "metrics.json").write_text(
    json.dumps(metrics, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
```

- `json.dumps()`: 딕셔너리를 JSON 문자열로 변환.
- `ensure_ascii=False`: 한글 등을 유니코드 이스케이프 대신 문자 그대로 표현.
- `indent=2`: JSON 문자열에 2칸 들여쓰기 적용.
- `write_text()`: 변환한 문자열을 실제 파일에 기록.
- `encoding="utf-8"`: 파일에 기록할 문자 인코딩 지정.

원래 붙여넣은 코드에서는 `encoding`이 `json.dumps()` 안에 있었지만, 위처럼 `write_text()`의 인자로 옮겨야 한다.

정리하면, Dictionary는 메모리의 데이터이고, JSON은 문자열 형식이며, Path는 그 문자열을 저장할 경로와 파일 작업을 담당한다.
