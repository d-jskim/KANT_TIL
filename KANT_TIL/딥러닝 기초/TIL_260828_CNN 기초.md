## 1. Train · Validation · Test와 Epoch

### 각 과정의 역할

| 구분 | Train | Validation | Test |
|---|---|---|---|
| 목적 | 가중치 학습 | 학습 중 성능 확인과 모델 선택 | 확정한 모델의 최종 성능 평가 |
| Loss 계산 | 학습 기준으로 사용 | 평가 지표로 사용 | 평가 지표로 사용 가능 |
| 역전파·가중치 업데이트 | 실행 | 실행하지 않음 | 실행하지 않음 |
| 진행 시점 | 여러 epoch 동안 반복 | 오늘의 구성에서는 매 epoch 학습 후 | 학습·모델 선택이 끝난 뒤 |

Epoch는 Train 데이터 전체를 한 번 학습하는 단위다. Epoch 자체가 학습과 검증을 합친 뜻은 아니다.

오늘 배운 학습 루프에서는 각 epoch의 학습이 끝날 때 검증을 붙인다.

```python
# 전체 흐름을 보여 주는 의사코드
for epoch in range(num_epochs):
    train_one_epoch(model, train_loader)  # 가중치 업데이트
    validate(model, valid_loader)         # 성능만 측정
    # 검증 결과로 모델 저장·EarlyStopping 여부 판단

# 학습 중 선택한 최종 모델로 평가
evaluate(final_model, test_loader)
```

Validation 결과는 학습 중단, 최적 모델 저장, 하이퍼파라미터 선택 등에 활용한다. Test는 최종 평가용으로 남겨 두고, 그 결과를 반복적으로 보며 모델을 고치는 데 사용하지 않는다.

### Validation loss는 왜 낮아질 수 있는가?

- 가중치를 직접 업데이트하는 기준은 Train loss다.
- Validation에서도 Train으로 업데이트된 같은 모델을 사용한다.
- Train에서 배운 공통 패턴이 Validation에도 통하면 Validation loss도 낮아질 수 있다.
- Train loss가 낮아져도 Validation loss가 반드시 낮아지는 것은 아니다.

Validation loss 그래프는 **학습이 끝난 모델 하나를 반복 평가한 기록이 아니라, 매 epoch 학습으로 달라진 모델을 평가한 기록**이다.

같은 가중치와 같은 평가 조건으로 검증만 반복한다고 성능이 저절로 좋아지지는 않는다.

### 학생 비유

A 교과서로 공부하고, 고정된 모의고사를 본다. 모의고사에서는 채점만 한다. 이후 A 교과서로 다시 공부한 뒤 같은 모의고사를 본다.
모의고사에서 틀린 문제를 직접 학습하지 않아도, A에서 배운 풀이법이 모의고사에 통하면 점수가 올라갈 수 있다.
보통 Validation은 같은 데이터와 같은 문제 비율로 평가한다. 점수가 흔들리더라도 학습으로 실력이 변하면 전체적으로 좋아지는 추세가 나타날 수 있다.

## 2. EarlyStopping: patience와 min_delta

```python
early_stopping = EarlyStopping(patience=3, min_delta=0.001)
```

| 항목 | 의미 |
|---|---|
| `patience=3` | 개선으로 인정되지 않는 검증이 연속 3회면 중단 |
| `min_delta=0.001` | 개선으로 인정할 최소 변화량의 기준 |

매 epoch 검증한다면 patience는 연속 미개선 epoch 수에 해당한다.

### 개선 판단과 카운터

- Validation loss는 작을수록 좋다.
- 직전 epoch가 아니라, 개선 판단에 사용하는 기존 best와 비교한다.
- 개선으로 인정되면 미개선 카운터를 0으로 초기화한다.
- 개선으로 인정되지 않으면 카운터를 1 증가시킨다.
- 총 3번이 아니라 **연속 3번** 개선이 없어야 멈춘다.

예를 들어 카운터가 2여도 다음 검증에서 개선되면 다시 0부터 센다.

### 아주 조금 좋아졌을 때

Best loss가 0.500이고 min_delta가 0.001인 경우:

| 현재 loss | 감소 폭 | 판단 |
|---|---|---|
| 0.4995 | 0.0005 | 개선으로 인정하지 않음 |
| 0.4980 | 0.0020 | 개선으로 인정 |

정확히 0.001 감소한 경계값까지 개선으로 인정하는지는 구현의 비교 조건에 달려 있다.

예를 들어 아래처럼 엄격한 부등호를 사용하면 0.001을 초과해서 줄어야 개선이다.

```python
is_improved = valid_loss < best_loss - min_delta
```

단순히 `valid_loss < best_loss`만 검사하는 구현이라면 아주 작은 감소도 개선으로 인정한다.

## 3. Linear · 활성화 함수 · fc · classifier

### Linear의 역할

Linear는 입력값에 가중치를 곱하고 편향을 더해 새로운 특성값을 만든다.

```python
self.fc1 = nn.Linear(input_dim, hidden_dim)
```

입력 특성 input_dim개를 조합해 출력 특성 hidden_dim개를 만드는 선형층 객체를 생성한다. 생성할 때 넣는 것은 실제 입력 데이터가 아니라 특성의 개수다.


### 모델 전체도 선형인가?

오늘 배운 MLP와 CNN은 선형 계산과 비선형 연산을 조합한 모델이다.
선형층만 여러 개 쌓으면 하나의 선형층으로 합칠 수 있다. ReLU 같은 비선형 활성화 함수를 넣어 복잡한 관계를 표현하도록 한다.
따라서 선형층을 사용한다고 모델 전체가 선형 함수인 것은 아니다.

## 4. Dropout: 역할과 작동 모드

### 왜 사용하는가?

학습 중 일부 활성값을 무작위로 0으로 만들어 특정 출력에 과도하게 의존하지 않도록 한다. 과적합을 억제하고 일반화를 돕는 것이 목적이다.
가중치를 삭제하거나 뉴런을 영구적으로 제거하는 것은 아니다. Dropout 자체에는 학습할 가중치가 없다.
Train 성능이 높다는 것만으로 과적합은 아니다. Train은 좋아지는데 Validation은 나빠지는 등의 차이를 함께 봐야 한다.

### 실제 계산

```python
dropout = nn.Dropout(p=0.3)

dropout.train()
y_train = dropout(x)

dropout.eval()
y_eval = dropout(x)
```

| 코드 | 의미 |
|---|---|
| `nn.Dropout(p=0.3)` | 각 값을 0으로 만들 확률이 0.3인 층 객체 생성 |
| `dropout.train()` | 학습 모드로 설정, Dropout 활성화 |
| `dropout(x)` | 현재 모드에 따라 실제 데이터 처리 |
| `dropout.eval()` | 평가 모드로 설정, Dropout 비활성화 |

학습 모드에서는 일부 값을 0으로 만들고, 남은 값은 `1 / (1 - p)`배로 보정한다. 예를 들어 p=0.5라면 남은 값은 2배가 된다.
평가 모드에서는 입력을 그대로 반환한다. 입력과 출력의 shape는 두 모드 모두 같다.

### train()과 eval()은 학습·검증 실행 명령이 아니다

- `train()`과 `eval()`은 작동 모드를 설정한다.
- `dropout(x)`는 해당 층의 순전파 계산이다.
- 이것만으로 역전파, 가중치 업데이트, 검증 점수 계산까지 진행되지는 않는다.
- `eval()` 자체가 자동으로 gradient 계산을 끄는 것도 아니다. 평가에서는 보통 `torch.no_grad()` 등을 함께 사용한다.

### 왜 평가할 때도 Dropout을 호출하는가?

평가 시 Dropout을 직접 건너뛰어도 되지만, 실제 모델에서는 같은 forward 코드를 유지하는 것이 편리하다.
`model.eval()`로 내부 Dropout을 비활성화하면, 같은 `model(x)` 호출에서 Dropout이 입력을 그대로 통과시킨다.

### nn.Module과 하위 층의 모드

```python
self.dropout = nn.Dropout(p=dropout_p)
```

이렇게 저장한 Dropout은 모델의 하위 모듈로 등록된다.
`model.train()`과 `model.eval()`은 등록된 하위 모듈들에도 모드 설정을 전달한다. 따라서 내부 Dropout도 함께 켜지거나 꺼진다.

### 오늘 수정한 오류

```python
# 모델 내부의 Dropout이 아니라 외부 변수를 참조
x = dropout(x)

# 모델에 등록한 Dropout 사용
x = self.dropout(x)
```

외부 dropout이 eval 모드였다면 model.train()으로도 그 외부 객체는 켜지지 않는다. 모델에 등록된 층을 사용하려면 self.dropout(x)로 호출해야 한다.

## 5. BatchNorm: 목적과 배치 구성

### 역할

학습 중 각 특성·채널의 배치 평균과 분산으로 활성값을 정규화하고, 학습 가능한 크기·위치 조절을 적용한다.
중간 활성값의 규모를 조절해 학습의 안정성과 수렴을 돕는 것이 목적이다. 모든 값을 같게 만드는 것은 아니다.
기본 설정의 평가 모드에서는 현재 배치의 통계가 아니라 학습 중 누적한 평균·분산을 사용한다.

### BatchNorm1d와 BatchNorm2d

N은 배치 크기, C는 특성·채널 수, L은 길이, H와 W는 높이·너비다.

| 구분 | 입력 shape | 학습 중 통계 계산 범위 |
|---|---|---|
| BatchNorm1d | (N, C) | 각 특성별로 N개 값 |
| BatchNorm1d | (N, C, L) | 각 채널별로 N과 L 전체 |
| BatchNorm2d | (N, C, H, W) | 각 채널별로 N, H, W 전체 |

`BatchNorm2d(16)`의 16은 배치 크기가 아니라 채널 수다.
오늘의 구성에서는 Linear 출력에 BatchNorm1d, Conv2d 출력에 BatchNorm2d를 연결한다.

### 배치별로 정규화하면 중요한 차이가 사라지지 않는가?

다음 두 그룹은 평균만 다르고 분산은 같다.

- 첫 그룹: [11, 12, 13, 14, 15], 평균 13
- 둘째 그룹: [61, 62, 63, 64, 65], 평균 63

각각 자기 평균을 빼면 둘 다 [-2, -1, 0, 1, 2]가 된다. 표준편차도 같으므로 각각 별도의 배치로 정규화하면 같은 결과가 나온다.
원래의 절대적인 크기가 분류 단서였다면 그 차이를 잃을 수 있다. 정규화 결과만으로 원래 평균 13과 63을 구분할 수는 없다.
반면 두 그룹이 한 배치에 함께 들어가면 공통 평균·표준편차를 사용하므로 두 그룹의 차이가 남는다.
이 우려는 쓸데없는 것이 아니라 **배치 구성이 치우쳤을 때 생길 수 있는 실제 문제**다.

### Shuffle과 Stratify의 구분

- 클래스별로 데이터가 몰리면 연속된 업데이트와 BatchNorm 통계가 특정 클래스에 치우칠 수 있다.
- Shuffle은 각 배치가 전체 분포를 더 잘 대표하도록 돕는다.
- Stratify는 보통 Train·Valid·Test 분할의 클래스 비율을 유지한다.
- Stratify가 매 배치의 클래스 비율까지 보장하는 것은 아니다.
- 입력과 정답은 항상 짝을 유지한다.

## 6. Linear → BatchNorm → ReLU → Dropout의 이유

| 단계 | 역할과 다음 단계로 이어지는 이유 |
|---|---|
| Linear | 입력을 조합해 새로운 특성을 만든다. 계산된 값의 규모를 조절할 필요가 있다. |
| BatchNorm | 특성값의 규모를 정돈해 학습을 돕는다. 그다음 비선형 변환을 적용한다. |
| ReLU | 음수는 0으로 만들고 양수는 통과시켜 비선형성을 넣는다. |
| Dropout | 만들어진 출력 일부를 무작위로 가려 특정 출력에 대한 의존을 줄인다. |

이 구성은 **특성 생성, 규모 조절, 비선형 변환, 과도한 의존 억제**의 흐름이다.

Dropout을 BatchNorm 바로 앞에 두면 무작위로 가려진 값으로 평균·분산을 계산하게 된다. 평가에서는 Dropout이 꺼지므로 입력 분포와 누적 통계가 어긋날 수 있어, 이 구성에서는 BatchNorm 뒤에 Dropout을 둔다.

## 7. CNN: Kernel · Padding · Dilation

### Conv2d의 채널

```python
self.conv1 = nn.Conv2d(
    in_channels=3,
    out_channels=16,
    kernel_size=3,
    padding=1
)
```

입력 채널 3개를 받아 출력 채널 16개를 만든다. 기본 stride=1, dilation=1에서 kernel_size=3과 padding=1을 사용하면 높이·너비는 유지된다.
따라서 입력이 (N, 3, 32, 32)이면 출력은 (N, 16, 32, 32)다.

### Padding과 커널 중심

Padding은 입력 바깥에 여백을 추가하는 것이다. 기본 zero padding에서는 0으로 채운다.

| 커널 크기 | 중심에서 가장자리까지 거리 | 중심을 원본 (0, 0)에 맞출 패딩 |
|---|---|---|
| 3×3 | 1칸 | 상하좌우 각각 1 |
| 5×5 | 2칸 | 상하좌우 각각 2 |

Stride=1, dilation=1인 홀수 커널에서 입력·출력 크기를 유지하려면 다음 값을 사용한다.

`padding = (kernel_size - 1) / 2`

Kernel이 3이라고 padding이 반드시 1인 것은 아니다. 더 큰 padding도 설정할 수 있으며, 원하는 출력 크기와 경계 처리 방식에 따라 선택한다.

### Padding이 없으면 가장자리 정보가 삭제되는가?

가장자리 값도 합성곱 계산에 포함된다. 입력의 테두리를 그대로 잘라 버리는 것은 아니다.
3×3 커널, stride=1, padding=0이면 첫 커널의 중심은 원본 (1, 1)에 놓인다. 그 계산에도 원본 (0, 0)은 포함된다.
다만 가장자리를 중심으로 한 출력 위치를 만들 수 없으므로, 5×5 입력은 3×3 출력으로 줄어든다.
이 예에서는 모서리 픽셀은 1개 출력 계산에, 중앙 픽셀은 9개 출력 계산에 참여한다.

### Padding을 쓰는 이유

- 가장자리 위치를 중심으로도 특징을 계산할 수 있게 한다.
- 합성곱을 반복할 때 특성맵이 너무 빨리 작아지는 것을 막는다.
- 필요한 공간 크기를 유지하면서 여러 층을 쌓도록 돕는다.

3×3, stride=1에서 padding이 없으면 5×5가 3×3, 이후 1×1로 줄어든다. Padding=1이면 각 합성곱에서 5×5 크기를 유지할 수 있다.
값이 계산에 사용된다는 것과 모든 정보가 완전히 보존된다는 것은 다르며, padding 자체도 정보의 완전 보존을 보장하지 않는다.

### Dilation

Dilation은 커널의 각 가중치가 적용되는 입력 위치 사이의 간격이다. 가중치 수를 늘리지 않고 더 넓은 범위를 보게 한다.

| 3×3 커널 | 입력을 읽는 방식 | 한 번에 걸치는 범위 |
|---|---|---|
| dilation=1 | 이웃한 위치 | 3×3 |
| dilation=2 | 한 칸씩 건너뛴 위치 | 5×5 |

Dilation=2여도 5×5의 25개 값을 모두 계산하는 것은 아니다. 한 입력 채널에 대응하는 3×3 커널의 가중치 9개가 떨어져 있는 입력 9개에 적용된다.

- Stride: 커널 전체가 이동하는 간격.
- Dilation: 커널 내부에서 입력을 읽는 간격.

3×3, dilation=2, stride=1이면 출력 크기를 유지하는 padding은 2다.

## 8. Pooling

Pool은 “한데 모으다”라는 뜻이다. Pooling은 주변 여러 값을 모아 대표값 하나로 요약하는 연산이다.

| 종류 | 대표값 |
|---|---|
| Max Pooling | 최댓값 |
| Average Pooling | 평균 |

2×2 영역에 1, 3, 2, 4가 있다면 Max Pooling은 4, Average Pooling은 2.5를 남긴다.

```python
self.pool = nn.MaxPool2d(kernel_size=2)
```

이 설정은 기본적으로 stride도 2이므로, 높이·너비가 32×32에서 16×16으로 줄어든다. 채널 수는 그대로이며 학습할 가중치는 없다.
계산량을 줄이고 특징을 요약하는 대신 세부 정보 일부를 잃는다.
앞서 배운 구성에서는 padding으로 합성곱마다 자동으로 크기가 줄어드는 것을 막고, 필요한 지점에서 pooling으로 의도적으로 크기를 줄인다.

## 9. Flatten과 Linear의 연결

### Flatten의 역할

```python
x = torch.flatten(x, start_dim=1)
```

배치 차원은 유지하고, 이미지 한 장에 해당하는 나머지 차원을 하나로 펼친다.

(N, C, H, W)는 (N, C×H×W)가 된다. 값을 삭제하거나 개수를 줄이는 연산이 아니다.

### 텐서로도 계산할 수 있는데 왜 펼치는가?

펼치지 않은 텐서로도 계산할 수 있다. Flatten은 텐서 계산을 가능하게 만드는 필수 과정이 아니라, **이 구조의 Linear가 이미지 전체 특징을 입력으로 조합하도록 모양을 맞추는 과정**이다.

PyTorch의 Linear는 마지막 차원을 입력 특성으로 사용한다.

이미지 한 장의 특징을 [[1, 2], [3, 4]]라고 하고, 설명을 위해 가중치는 모두 1, 편향은 0이라고 하자.

| 구성 | 계산 | 결과 |
|---|---|---|
| 펼치지 않고 Linear(2, 1) | 각 행에서 1+2, 3+4 | 3과 7 |
| 펼친 뒤 Linear(4, 1) | 1+2+3+4 | 10 |

첫 구성의 Linear는 두 행을 자동으로 하나로 합쳐 주지 않는다. 두 번째 구성은 결과 하나를 만들 때 네 특징을 모두 사용한다.

### Flatten하면 위치를 잊는가?

값의 순서가 고정되어 있으므로 원래 채널·위치는 벡터의 특정 번호에 대응한다. Linear는 각 위치에 다른 가중치를 학습할 수 있다.

다만 높이·너비로 명시되어 있던 공간 모양은 하나의 축으로 바뀐다.

### CNN에서 출력층 직전에 Flatten한 이유

Conv2d와 MaxPool2d는 이웃한 값들의 공간 구조를 사용하므로, 그 처리가 끝날 때까지 (채널, 높이, 너비) 모양을 유지한다.
그다음 Linear 분류층에 전체 특징을 전달할 때 펼친다.
“출력층이므로 펼친다”가 아니라 **공간 구조를 사용하는 처리가 끝나고 Linear로 넘어가므로 펼친다**.
이전 MLP는 첫 층이 Linear였으므로 입력에서 바로 펼쳤다.

## 10. isinstance와 patience 타입 검사

`isinstance(값, 타입)`은 해당 타입 또는 그 하위 타입의 객체인지 확인한다. 변수의 존재 여부를 확인하는 함수가 아니다.

| 조건 | True가 되는 경우 |
|---|---|
| `isinstance(patience, bool)` | patience가 bool 타입 |
| `isinstance(patience, int)` | patience가 int 또는 그 하위 타입 |
| `not isinstance(patience, int)` | patience가 int 또는 그 하위 타입이 아님 |

not은 검사 결과를 뒤집는다. 값이 False여도 bool 타입인지 검사하면 True다.

```python
isinstance(False, bool)  # True
```

### 전체 조건

```python
isinstance(patience, bool) or not isinstance(patience, int)
```

“bool이거나 정수가 아닌가?”를 검사해, bool을 제외한 정수 타입만 받으려는 조건이다.

Python에서 bool은 int의 하위 타입이므로 bool을 따로 제외해야 한다.

```python
isinstance(True, int)   # True
isinstance(False, int)  # True
```

| patience 값 | 전체 조건 | 타입 검사 결과 |
|---|---|---|
| 3 | False | 통과 |
| True | True | 거부 |
| False | True | 거부 |
| 3.0 | True | 거부 |
| "3" | True | 거부 |
