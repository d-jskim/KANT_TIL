# TIL - LangChain PromptTemplate과 Chain 실행 흐름

## 1. ChatOpenAI 객체와 실제 모델 호출

`ChatOpenAI` 객체를 생성한다고 해서 OpenAI의 모델 자체가 내 Python 프로세스에 로드되는 것은 아니다.

```text
ChatOpenAI 객체 생성
→ OpenAI 모델을 호출하기 위한 설정 및 인터페이스 준비
→ model.invoke() 실행
→ OpenAI API 요청
→ 원격 모델 실행
→ 응답 반환
```

`ChatOpenAI(...)`는 원격 모델을 사용하기 위한 객체이며, 실제 API 요청은 `model.invoke()`를 실행할 때 발생한다.

API Key가 환경변수에 존재하는 것과 실제로 유효한 것은 다르다. 실제 API 요청 시 서버에서 인증이 이루어진다.

---

## 2. `.env`와 `load_dotenv()`

`.env`에는 API Key, 모델명 등 코드에서 분리하고 싶은 환경 설정값을 저장할 수 있다.

```text
.env
→ load_dotenv()
→ 현재 Python 프로세스의 환경변수
→ os.getenv()
```

`override=True`를 사용하면 기존 환경변수와 같은 이름의 값이 있을 때 `.env`의 값으로 덮어쓴다.

```python
load_dotenv(override=True)
```

단, `override=True`는 어떤 `.env`를 찾을지 결정하는 옵션이 아니다.

이번 실습에서는 `.env`의 위치 때문에 기존 API Key가 사용되어 `401 AuthenticationError`가 발생했고, `.env`를 프로젝트 최상위 폴더로 이동한 뒤 정상적으로 동작했다.

## 3. PromptTemplate

`PromptTemplate`은 실행할 때 달라지는 값을 변수로 두고 동일한 프롬프트 구조를 반복해서 사용할 수 있게 한다.

```python
template = PromptTemplate.from_template(
    "주제: {topic}\n"
    "독자 수준: {audience}\n"
    "주제를 한 문장으로 설명하세요."
)
```

`topic`, `audience`는 `PromptTemplate`에 원래 존재하는 고정 속성이 아니라 개발자가 정의한 입력 변수이다.

```python
formatted_prompt = template.format(
    topic="LangChain",
    audience="파이썬 입문자"
)
```

`.format()`은 모델을 호출하는 것이 아니라 변수에 실제 값을 넣어 완성된 프롬프트를 만드는 과정이다.

## 4. PromptTemplate의 실제 서비스 활용

실제 서비스에서는 사용자가 모든 값을 직접 입력할 필요가 없다.

예를 들어 Job-Skill Matching 서비스라면 사용자 입력과 서비스가 보유한 정보를 함께 사용할 수 있다.

```text
사용자 입력
→ 채용공고 JD

사용자 프로필
→ 경력
→ 학력
→ 보유 스킬
→ 이전 직무

서비스 Context
→ 커리큘럼
→ 평가 기준

        ↓

PromptTemplate

        ↓

표준화된 LLM 입력
```

예를 들어 다음과 같은 프롬프트 구조를 만들 수 있다.

```text
지원자 정보
- 경력: {career}
- 학력: {education}
- 보유 스킬: {skills}

채용공고
{job_description}

지원자와 채용공고의 적합도를 분석하세요.
```

중요한 점은 `PromptTemplate`이 사용자의 경력이나 수준을 스스로 알아내는 것이 아니라는 것이다.

```text
데이터 조회
→ 애플리케이션

프롬프트 구성
→ PromptTemplate

추론
→ LLM

결과 처리
→ Parser 또는 애플리케이션 로직
```

## 5. 요약 프롬프트 실습

요약은 긴 원문의 핵심 내용을 유지하면서 더 짧게 압축하는 작업이다.

처음 예제는 이미 한 문장인 원문을 세 문장으로 요약하도록 되어 있어 실제로는 요약보다 확장 설명에 가까웠다.

```text
원문 1문장
→ "세 문장으로 요약하세요."
→ 모델이 내용을 추가하거나 풀어서 설명할 가능성
```

따라서 실제 요약 실습에서는 충분히 긴 원문을 입력하고 세 문장으로 줄이는 방식이 더 적절하다.

또한 원문에 없는 내용을 추가하지 않도록 명시할 수도 있다.

```python
summary_template = PromptTemplate.from_template(
    "독자 수준: {audience}\n"
    "다음 글을 독자 수준에 맞춰 정확히 세 문장으로 요약하세요.\n"
    "원문에 없는 내용은 추가하지 마세요.\n\n"
    "글:\n{text}"
)
```

## 6. `invoke()`의 의미

`invoke`는 호출하다, 실행시키다라는 의미이다.

LangChain에서는 간단히 다음과 같이 이해할 수 있다.

```text
invoke(input)
= 이 객체에 input을 주고 한 번 실행
```

모델도 `invoke()`할 수 있다.

```python
ai_message = model.invoke(prompt)
```

Parser도 `invoke()`할 수 있다.

```python
result = parser.invoke(ai_message)
```

Chain 전체도 `invoke()`할 수 있다.

```python
result = chain.invoke(input)
```

---

## 7. 왜 `parser.parse()`가 아니라 `invoke()`인가?

각 객체는 원래 서로 다른 역할을 가진다.

```text
Prompt → 프롬프트 구성
Model → 모델 호출
Parser → 결과 파싱
```

역할에 따라 각각 다른 메서드를 사용하도록 만들 수도 있다.

```text
prompt.format()
model.generate()
parser.parse()
```

하지만 LangChain에서는 여러 구성 요소를 `Runnable`이라는 공통 실행 구조로 다룬다.

```text
PromptTemplate   → invoke()
ChatOpenAI       → invoke()
OutputParser     → invoke()
Chain            → invoke()
```

즉 `invoke()`는 각 객체의 구체적인 기능 이름이라기보다 LangChain 구성 요소를 실행하기 위한 공통 인터페이스이다.

## 8. `|` 연산자와 Chain

Python의 `|`는 원래 OR 등에 사용하는 연산자이지만 LangChain에서는 연산자 오버로딩을 통해 객체를 연결하는 데 사용한다.

```python
summary_chain = summary_template | model | StrOutputParser()
```

실행 흐름은 다음과 같다.

```text
최초 입력
   ↓
PromptTemplate
   ↓
Prompt output
   ↓
ChatOpenAI
   ↓
AIMessage
   ↓
StrOutputParser
   ↓
str
```

핵심은 앞 객체의 `output`이 다음 객체의 `input`으로 전달된다는 것이다.

직접 실행한다면 개념적으로 다음과 같다.

```python
prompt_output = prompt.invoke(input)
ai_message = model.invoke(prompt_output)
result = parser.invoke(ai_message)
```

Chain으로 연결하면 한 번만 호출하면 된다.

```python
chain = prompt | model | parser
result = chain.invoke(input)
```

즉 `|`는 다음과 같이 이해할 수 있다.

```text
앞 단계의 output
        ↓
다음 단계의 input
```

## 9. 직접 호출과 Chain 비교

직접 호출:

```text
PromptTemplate.format()
→ model.invoke()
→ response.content
```

Chain:

```text
PromptTemplate
→ ChatOpenAI
→ StrOutputParser
→ chain.invoke()
```

두 방식 모두 결국 모델 API를 호출한다.

Chain의 장점은 여러 처리 단계를 하나의 실행 흐름으로 연결하고 동일한 `invoke()` 인터페이스로 실행할 수 있다는 것이다.

실행 시간 비교 시 대부분의 시간은 LLM API 요청과 모델 응답 생성에 사용되므로, 한 번의 측정만으로 Chain 자체가 더 빠르거나 느리다고 판단해서는 안 된다.

## 오늘의 핵심

```text
PromptTemplate
= 동적으로 변하는 데이터를 일정한 프롬프트 구조로 조립

ChatOpenAI
= 원격 LLM을 호출하기 위한 객체

invoke()
= LangChain 객체의 공통 실행 인터페이스

|
= 앞 단계의 output을 다음 단계의 input으로 연결

StrOutputParser
= 모델의 출력을 필요한 형태로 변환

Chain
= 여러 Runnable을 하나의 실행 흐름으로 연결
```

오늘 가장 중요한 흐름은 다음과 같다.

```text
사용자/서비스 데이터
        ↓
PromptTemplate
        ↓
Model
        ↓
Parser
        ↓
애플리케이션에서 사용할 결과
```
