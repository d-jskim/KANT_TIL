# TIL - 2026.10.01

## 1. LangChain Document

`Document`는 LangChain에서 문서를 표현하기 위해 제공하는 객체다.

```python
from langchain_core.documents import Document

document = Document(
    page_content="Retriever는 관련 문서를 검색합니다.",
    metadata={
        "title": "Retriever 역할",
        "source": "retriever_note.md",
    },
)
```

주요 구성은 다음과 같다.

- `page_content`: 실제 문서 내용
- `metadata`: 제목, 출처 등 문서에 대한 부가 정보

`Document` 클래스는 LangChain에 이미 정의되어 있으므로 직접 클래스를 선언할 필요가 없다.

여러 문서는 다음처럼 관리할 수 있다.

```python
documents: list[Document] = [
    Document(...),
    Document(...),
]
```

현재 실습에서는 별도의 저장소를 사용하지 않기 때문에 `Document` 객체를 Python 리스트에 직접 저장한다.

## 2. Retriever

Retriever는 사용자 질의와 관련된 `Document`를 찾아 다음 단계에 전달하는 검색 인터페이스다.

이번 실습에서는 각 문서의 `metadata`에 검색용 키워드를 저장했다.

```python
metadata={
    "keywords": ["retriever", "검색", "질의", "문서"],
}
```

질문에 포함된 키워드와 문서의 `keywords`를 비교하여 검색 점수를 계산한다.

```text
사용자 질의
    ↓
문서별 keyword 비교
    ↓
일치하는 keyword 수 계산
    ↓
점수가 높은 문서 선택
    ↓
관련 Document 반환
```

따라서 이번 Retriever는 Embedding이나 Vector Search를 사용하는 것이 아니라 직접 만든 키워드 기반 Retriever다.

## 3. RunnableLambda로 Retriever 만들기

일반 Python 검색 함수를 `RunnableLambda`로 감싸 LangChain의 Runnable로 만들 수 있다.

```python
def retrieve(query: str) -> list[Document]:
    return search_documents(query, documents)

retriever = RunnableLambda(retrieve)
```

이렇게 만들면 Retriever를 `invoke()`로 실행할 수 있다.

```python
results = retriever.invoke(query)
```

흐름은 다음과 같다.

```text
질의
  ↓
Retriever.invoke()
  ↓
retrieve()
  ↓
문서 검색
  ↓
list[Document]
```

즉 이전에 학습한 `Runnable`과 `invoke()`가 Retriever에서도 동일하게 사용된다.

## 4. 실제 RAG에서의 Document와 Vector Store

이번 실습에서는 `list[Document]`를 검색하지만 실제 벡터 기반 RAG에서는 문서를 Embedding하여 Vector Store에 저장하고 검색할 수 있다.

```text
원본 문서
    ↓
Document
    ↓
Chunk 분할
    ↓
Embedding
    ↓
Vector Store
    ↓
Retriever
```

질문이 들어오면 질문도 Embedding하여 관련 문서를 찾는다.

```text
사용자 질문
    ↓
Embedding
    ↓
Vector 유사도 검색
    ↓
관련 Document 검색
    ↓
LLM에 Context로 전달
```

따라서 역할을 구분하면 다음과 같다.

| 개념 | 역할 |
|---|---|
| `Document` | 문서 내용과 metadata를 표현 |
| Vector Store | Embedding된 문서를 저장하고 검색 |
| Retriever | 질의와 관련된 문서를 검색하여 반환 |

## 5. InMemoryChatMessageHistory

`InMemoryChatMessageHistory`는 대화 메시지를 메모리에 저장하는 객체다.

```python
history = InMemoryChatMessageHistory()
```

여러 세션의 대화 기록을 분리하려면 세션 ID와 각각의 `InMemoryChatMessageHistory`를 연결해서 관리할 수 있다.

```python
store: dict[str, InMemoryChatMessageHistory] = {}
```

개념적으로는 다음과 같다.

```text
store
├─ "session-a" → session-a의 대화 기록
├─ "session-b" → session-b의 대화 기록
└─ "session-c" → session-c의 대화 기록
```

따라서 같은 세션에서는 기존 대화 기록을 이어서 사용할 수 있고, 다른 세션의 기록과는 분리할 수 있다.

현재 사용 중인 LangChain에서는 `InMemoryChatMessageHistory`가 deprecated 상태이므로, 현재 교안의 개념 학습에는 사용할 수 있지만 향후 새로운 방식으로 대체될 예정이다.

## 오늘의 핵심

오늘은 LangChain에서 데이터를 검색하고 대화 기록을 관리하는 기본 구조를 확인했다.

```text
문서 검색
Document
   ↓
Retriever
   ↓
관련 Document

대화 기록
session_id
   ↓
InMemoryChatMessageHistory
   ↓
세션별 history
```

Retriever는 관련 문서를 찾아 다음 단계에 전달하고, `InMemoryChatMessageHistory`는 세션별 대화 내용을 저장하는 역할을 한다.
