## FastAPI 데코레이터

```python
@app.post(
    "/users",
    response_model=UserResponse,
    status_code=status.HTTP_201_CREATED,
)
def create_user(request: UserCreate) -> UserResponse:
    ...
```

- `"/users"`: 요청 URL
- `request: UserCreate`: 클라이언트가 보내는 요청 형식
- `response_model=UserResponse`: 서버가 반환하는 응답 형식
- `status_code=201`: 새로운 데이터 생성 성공
- `-> UserResponse`: 함수가 반환할 값의 자료형 표시

`response_model`은 요청으로 받는 데이터가 아니라 서버가 반환할 데이터의 구조를 의미한다.

## Pydantic의 역할

Pydantic 모델은 API로 들어온 JSON을 Python 객체로 변환하고, 필드의 자료형과 검증 조건을 확인한다.

```python
class UserCreate(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True)

    name: str = Field(min_length=2, max_length=100)
```

클라이언트 요청:

```json
{
  "name": "테스트 사용자"
}
```

FastAPI가 JSON을 `UserCreate` 객체로 변환하면 다음과 같이 값에 접근할 수 있다.

```python
request.name
```

- `BaseModel`: 요청·응답 데이터 구조 정의
- `Field`: 길이, 범위 등의 검증 조건 정의
- `str_strip_whitespace=True`: 문자열 앞뒤 공백 제거
- 검증 실패: API 함수 실행 전에 `422 Unprocessable Entity` 반환

## 요청 모델과 응답 모델

```python
class UserCreate(BaseModel):
    name: str


class UserResponse(UserCreate):
    user_id: int
```

- 요청 모델: 클라이언트가 입력해야 하는 필드
- 응답 모델: 서버가 생성한 값을 포함해 반환하는 필드
- 상속을 사용하면 공통 필드를 다시 작성하지 않아도 됨

```text
UserCreate
└─ name

UserResponse
├─ name
└─ user_id
```

`user_id`는 클라이언트가 입력하는 값이 아니라 DB가 생성하는 값이다.

## 사용자와 Career Profile

사용자와 Career Profile은 서로 다른 엔터티이다.

```text
사용자
├─ LLM 엔지니어 지원용 프로필
├─ Product Designer 지원용 프로필
└─ 특정 기업 지원용 프로필
```

- `career_user.name`: 사용자 이름
- `career_profile.profile_name`: 프로필을 구분하는 제목
- 한 사용자는 여러 Career Profile을 가질 수 있음
- 사용자와 Career Profile은 `user_id`로 연결

Career Profile 생성 요청:

```json
{
  "user_id": 1,
  "profile_name": "LLM 엔지니어 지원용"
}
```

## Skill 관계 설계

Skill은 특정 프로필에 반복해서 저장하기보다 사용자의 전체 역량으로 관리할 수 있다.

```text
career_user
 ├─ career_profile
 └─ user_skill ─ skill
```

`user_skill`은 사용자와 Skill을 연결하는 중간 테이블이다.

```sql
PRIMARY KEY (user_id, skill_code)
```

복합 기본 키의 역할:

- 같은 사용자에게 같은 Skill이 중복 연결되는 것을 방지
- 사용자와 Skill의 조합 자체를 하나의 관계로 식별
- 별도의 연결 ID 없이 관계를 표현

별도 ID와 `UNIQUE (user_id, skill_code)`를 사용하는 방법도 있지만, 단순 연결 테이블에서는 복합 기본 키가 더 간단하다.

## 외래 키

```sql
FOREIGN KEY (user_id)
REFERENCES career_user(user_id)
```

외래 키는 존재하지 않는 사용자의 프로필이나 Skill 연결이 저장되는 것을 방지한다.

API에서는 외래 키 오류가 발생하기 전에 사용자의 존재 여부를 먼저 확인할 수 있다.

```python
cursor.execute(
    "SELECT user_id FROM career_user WHERE user_id = %s",
    (request.user_id,),
)
```

사용자가 없으면 `404 Not Found`를 반환한다.

## SQL 매개변수

SQL 문자열에 사용자 값을 직접 연결하지 않고 `%s` 자리에 별도로 전달한다.

```python
cursor.execute(
    "INSERT INTO career_user (name) VALUES (%s)",
    (request.name,),
)
```

한 개의 값을 SQL 매개변수로 전달할 때도 튜플이 필요하다.

```python
(request.name,)   # 한 항목짜리 튜플
(request.name)    # 단순 문자열 또는 값
```

쉼표가 있어야 Python이 한 항목짜리 튜플로 인식한다.

## DB 연결 함수

```python
connection = get_db_connection()
cursor = connection.cursor()
```

- `get_db_connection`: 함수 자체
- `get_db_connection()`: 함수를 실행해 반환받은 DB 연결 객체
- `cursor`: SQL을 실행하고 결과를 읽는 객체

DB 변경을 확정하려면 `commit()`이 필요하다.

```python
connection.commit()
```

사용이 끝난 자원은 닫아야 한다.

```python
finally:
    cursor.close()
    connection.close()
```

`finally`는 정상 처리와 오류 발생 여부에 관계없이 실행된다.

## 환경변수

DB 접속 정보는 코드에 직접 작성하지 않고 환경변수로 관리한다.

```python
mysql.connector.connect(
    host=os.getenv("DB_HOST"),
    port=int(os.getenv("DB_PORT", "3306")),
    user=os.getenv("DB_USER"),
    password=os.getenv("DB_PASSWORD"),
    database=os.getenv("DB_NAME"),
)
```

환경변수로 분리하는 이유:

- 비밀번호의 Git 노출 방지
- 개발·테스트·운영 환경별 설정 분리
- 코드 수정 없이 접속 정보 변경

`.env` 파일은 Git에 올리지 않고 `.gitignore`에 포함해야 한다.

## 메모리 저장소와 MySQL

Python 딕셔너리는 간단한 API 흐름을 확인하기에 적합하다.

```python
PROFILES: dict[int, ProfileResponse] = {}
```

```text
key   → profile_id
value → ProfileResponse
```

| 메모리 딕셔너리 | MySQL |
|---|---|
| 코드가 단순함 | 테이블 설계가 필요함 |
| 서버 종료 시 데이터가 사라짐 | 데이터가 유지됨 |
| 한 프로세스에서 사용 | 여러 요청과 서비스가 공유 가능 |
| 관계와 검색 기능이 제한적 | 외래 키와 인덱스 사용 가능 |

메모리 저장소는 API 흐름 학습에 적합하고, 실제 서비스 데이터는 DB에 저장하는 것이 적합하다.

## 서비스 분리

서비스는 테이블마다 나누는 것이 아니라 관련된 업무 책임을 기준으로 분리한다.

```text
Profile Service
- 사용자
- Career Profile
- 사용자 Skill

Match Service
- 채용공고
- Skill 비교
- 매칭 결과
```

서로 다른 서비스는 별도의 포트를 사용할 수 있다.

```text
Profile Service → 8001
Match Service   → 8002
```

Match Service에서 Profile Service의 정보가 필요하면 HTTP 요청으로 조회한다.

```text
클라이언트
→ Match Service
→ Profile Service
→ Match Service
→ 클라이언트
```

## 동기와 비동기

서비스 간 HTTP 통신은 응답을 기다리는 시간이 발생한다.

```python
async with httpx.AsyncClient() as client:
    response = await client.get(url)
```

- `async`: 비동기 함수를 정의
- `await`: 외부 응답을 기다림
- 대기 시간 동안 서버가 다른 요청을 처리할 수 있음

DB 연산처럼 짧고 단순한 코드까지 모두 비동기로 만들 필요는 없다. 외부 API나 다른 서버를 기다리는 작업에서 비동기 처리의 효과가 크다.

## HTTP 상태 코드

| 코드 | 의미 |
|---|---|
| `200 OK` | 조회 성공 |
| `201 Created` | 새로운 데이터 생성 성공 |
| `404 Not Found` | 요청한 데이터가 없음 |
| `409 Conflict` | 현재 데이터 상태와 요청이 충돌 |
| `422 Unprocessable Entity` | 요청 데이터 검증 실패 |
| `500 Internal Server Error` | 서버 내부 처리 오류 |

상태 코드는 성공과 실패뿐 아니라 실패 원인의 종류도 클라이언트에게 전달한다.

## Swagger

FastAPI는 작성한 경로와 Pydantic 모델을 바탕으로 API 문서를 자동 생성한다.

```text
http://127.0.0.1:8001/docs
```

Swagger에서 확인할 수 있는 항목:

- HTTP Method
- URL
- Request body
- Response schema
- Status code
- 실제 API 실행 결과

Swagger의 입력 필드가 예상과 다르면 현재 서버가 사용하는 Pydantic 모델을 확인해야 한다.

## Git

Git은 코드의 현재 상태만 저장하는 것이 아니라 변경 과정을 커밋 단위로 기록한다.

```bash
git status --short
```

변경·추가된 파일 상태 확인:

```text
A  새로 추가된 파일
M  수정된 파일
?? 아직 추적하지 않는 파일
```

```bash
git diff --cached --check
```

커밋할 파일의 불필요한 공백과 줄 끝 문제 확인.

```bash
git commit -m "커밋 메시지"
```

현재 Stage에 올라간 변경사항을 하나의 버전으로 기록.

```bash
git push origin main
```

로컬 커밋을 GitHub 원격 저장소에 전송.

이전 버전의 파일은 커밋 ID를 사용해 다시 확인할 수 있다.

```bash
git show <commit-id>:<file-path>
```

따라서 메모리 딕셔너리 버전과 MySQL 버전을 각각 커밋으로 남기면 구현 방식의 발전 과정을 비교할 수 있다.

## 핵심 정리

1. FastAPI 데코레이터는 URL, 응답 모델, 상태 코드를 API 계약으로 정의한다.
2. 요청 데이터 형식은 함수 매개변수의 Pydantic 모델이 결정한다.
3. `response_model`은 서버가 반환하는 데이터 형식을 의미한다.
4. Pydantic은 API 함수 실행 전에 입력값을 검증한다.
5. 사용자와 Career Profile은 별도 엔터티이며 `user_id`로 연결된다.
6. 사용자의 Skill은 중간 테이블을 이용해 표준 Skill과 연결할 수 있다.
7. SQL 매개변수는 문자열에 직접 연결하지 않고 별도로 전달한다.
8. DB 변경사항은 `commit()`으로 확정한다.
9. DB 접속 정보는 환경변수로 관리한다.
10. 서비스는 테이블이 아니라 업무 책임을 기준으로 분리한다.
11. 외부 서비스 응답을 기다리는 작업에는 비동기 처리를 사용할 수 있다.
12. Git 커밋은 구현 과정과 이전 버전을 보존한다.
