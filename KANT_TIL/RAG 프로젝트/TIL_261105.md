## 1. RAG 실험의 변인 통제

세 가지 RAG 방식을 비교할 때 검색 방식 외의 조건은 동일하게 유지해야 함.

- 동일한 PDF
- 동일한 Chunk
- 동일한 Embedding Model
- 동일한 Vector DB와 Collection
- 동일한 생성 모델과 프롬프트
- 동일한 평가 질문과 평가 기준

Qdrant 사용 시 RAG 방식별 Instance·Collection 분리보다 동일 Collection을 공유하고 검색 파이프라인만 변경하는 방식이 적합함.

## 2. 세 가지 RAG 방식의 차이

- Naive RAG: Dense Vector 검색
- Hybrid RAG: Dense Vector 검색과 BM25 결과 결합
- Hybrid+Reranker: Hybrid 검색 후보의 관련도 재정렬

Embedding과 저장소 변경이 아니라 검색 및 재정렬 방식의 차이로 비교해야 함.

## 3. LangChain Document의 역할

LangChain Document는 기술 문서가 아니라 텍스트와 Metadata를 묶는 데이터 객체임.

- `page_content`: PDF에서 추출한 본문
- `metadata`: 문서 ID, 페이지, 파일명 등

PDF 처리 흐름:

```
PDF
→ pypdf 텍스트 추출
→ LangChain Document 변환
→ Chunk 분할
→ E5 Embedding
→ Qdrant 저장
```

Document Metadata를 통해 검색 결과의 문서 ID와 페이지 추적 가능

## 4. 평가 질문과 정답의 사용 시점

- 질문 JSON: 실제 사용자 질문으로 사용
- 정답 JSON: 답변 생성 이후 채점에만 사용
- 참고 답변·필수 사실·금지 주장·채점 근거의 검색 입력 제외

팀이 선택한 질문 전체를 세 RAG 방식으로 실행하고 모든 결과에 동일한 평가 적용

## 5. RAG 평가 항목

### 검색 평가

- Hit@k: 정답 문서가 검색 결과에 포함되었는지 확인
- Recall@k: 필요한 정답 문서를 얼마나 검색했는지 확인

### 답변 평가

- RAGAS Faithfulness: 답변이 검색 근거에 충실한지 평가
- LLM-as-a-Judge: 사실·조건·근거·판단 평가

### 운영 평가

- 응답 시간
- 오류율
- 입력·출력 토큰
- 모델 호출 비용

검색 정확도뿐 아니라 답변 품질과 운영 효율을 함께 비교해야 함.

## 6. 권한 기반 RAG 처리

문서 접근권한은 답변 생성 이후가 아니라 검색 이전 단계에 적용해야 함.

```
사용자 확인
→ 역할·대상·유효기간 확인
→ 검색 범위 제한
→ 허용된 Chunk 검색
→ LLM 입력
```

비공개 내용을 LLM에 전달한 후 숨기도록 지시하는 방식은 정보 노출 위험 존재

제조 데이터에서 확인한 권한 요소:

- 조회자·기록담당·검토자
- 조회·작성·검토·내보내기 권한
- 허용 대상 모델
- 권한 유효기간
- 승인과 실제 반영 상태

## 7. 보안 평가와 접근권한의 차이

제공된 보안 평가는 사용자 로그인 권한이 아니라 문서에 포함된 공격 지시 방어 평가임.

- Indirect Prompt Injection
- Context Poisoning
- 잘못된 주장의 채택 여부
- 불리한 근거 누락 유도

접근권한 테스트와 Prompt Injection 방어 평가는 별도 목적과 시나리오로 관리 필요

## 8. RDB와 Vector DB의 역할

### RDB

- 사용자
- 조직과 역할
- 접근권한
- 문서 버전
- 채팅 이력
- 답변 상태
- 인용 근거

### Vector DB

- Chunk
- Embedding Vector
- 검색 Metadata
- 유사도 검색

사용자·권한·이력은 RDB, 의미 검색 대상은 Vector DB로 분리

## 9. PDF 시각자료 제공 방식

사용자의 시각자료 요청은 두 유형으로 구분 가능

### 원본 시각자료 검색

PDF에 존재하는 표·그래프·페이지를 찾아 이미지로 표시

### 검색 결과 기반 시각화

PDF 표에서 추출한 수치로 새로운 표·그래프 생성

두 경우 모두 문서 ID·페이지·단위·기간·사용 값을 함께 제공하고 사용자 접근권한 적용 필요

## 10. 오늘의 핵심 정리

> 동일한 데이터와 저장소를 유지한 상태에서 검색 방식만 변경하여 RAG 성능을 비교하고, 검색 이전에 사용자 권한을 적용하여 허용된 근거만 LLM에 전달하는 구조가 필요함.
